# Authentication demonstration

This procedure demonstrates Prompt 04 with synthetic data only. It is not a production deployment guide. Never enter a real phone number, PIN, OTP, customer record, or banking credential.

## Prerequisites

- Git
- Node.js 22 as selected by `.nvmrc`
- pnpm 11.8.0
- Docker Desktop or Docker Engine with Compose v2
- A current passkey-capable browser
- Free local ports 3000, 4000, 4101, 5432, and 6379

## Environment setup

From the repository root:

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
```

Change every local-only password and its matching connection URL in the ignored `.env`. Keep `DEMO_AUTH_ENABLED=true` only for this local demonstration. Never commit `.env`.

## Start data services and migrations

Start Docker Desktop, then run:

```powershell
pnpm infra:validate
pnpm infra:up
pnpm infra:check
pnpm db:validate:identity
pnpm db:generate
pnpm db:deploy:identity
```

These commands preserve the named PostgreSQL and Redis volumes when services stop.

## Start the application

```powershell
pnpm dev
```

Wait for the web app, Gateway, and Identity service, then open `http://localhost:3000`.

## Demonstrate onboarding

1. Switch among English, Sinhala, and Tamil and confirm the page updates.
2. Choose **Create secure access**.
3. Enter a synthetic E.164 phone number reserved for the demonstration.
4. Select a language, accept consent, and request the verification code.
5. Enter the local demonstration OTP displayed by the page.
6. Create and confirm a non-obvious six-digit PIN.
7. Confirm that the completion view and `/app` display only masked customer data.

The displayed OTP exists only because the local API returned `demoOtp` with demo mode enabled. It is not guessed, generated by the web app, or suitable for production. Reloading the unfinished flow clears all sensitive in-memory state.

## Demonstrate passkey setup and sign-in

1. At onboarding or **Security settings**, choose **Add a passkey**.
2. Complete the browser or operating-system authenticator prompt.
3. Explain that biometric and device-unlock secrets remain on the device.
4. Log out.
5. Select **Sign in with passkey** and complete user verification.
6. Confirm the protected workspace reports passkey authentication.

If the demonstration device has no passkey support, show the explanatory unavailable state; do not claim that a ceremony completed.

## Demonstrate fallback sign-in

1. Log out and choose **Use phone, PIN and OTP**.
2. Enter the same synthetic phone and demonstration PIN.
3. Request and enter the new local demonstration OTP.
4. Confirm the protected workspace reports PIN and OTP authentication.

## Demonstrate logout and protection

Select **Log out**, then navigate directly to `http://localhost:3000/app`. The route must redirect to `/sign-in`. Explain that logout revokes the server session and clears authentication cookies.

## Stop all services

Press `Ctrl+C` in the application terminal, then run:

```powershell
pnpm infra:down
```

Confirm ports 3000, 4000, and 4101 have no project listeners and that the project containers are stopped. Do not delete named volumes during normal shutdown.
