# Authentication threat model

This model covers the browser and backend authentication path. All evidence uses synthetic identities. Browser passkey evidence uses a Chromium virtual authenticator; production authenticator and delivery-channel assurance remain outside this prototype.

| Threat                    | Asset and attack                                           | Mitigation                                                                                | Residual risk                                                               | Test or evidence                                       |
| ------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------ |
| Credential stuffing       | Customer account; automated reuse of phone/PIN pairs       | Generic failures, Argon2id, IP/phone limits, failed-attempt counters, temporary lock      | Distributed low-rate attacks remain possible                                | Fallback invalid-PIN and lockout e2e; PIN unit tests   |
| Account enumeration       | Registration status; compare unknown and incorrect users   | Same broad invalid-credential response and dummy Argon2 verification                      | Timing differences in external providers require monitoring                 | Fallback service tests and public response review      |
| OTP interception          | OTP second factor; attacker reads a delivered code         | Short TTL, one purpose, keyed digest at rest, second-factor binding                       | A compromised delivery channel can expose an active code                    | OTP digest/TTL unit tests                              |
| OTP replay                | Session creation; reuse a valid code                       | Atomic challenge consumption and one-time challenge IDs                                   | A race before consumption is bounded by Redis atomic operations             | OTP replay unit and onboarding e2e                     |
| PIN brute force           | PIN credential; repeated guesses                           | Argon2id, five-attempt temporary lock, OTP second factor                                  | Denial of service through temporary lock attempts                           | Temporary-lock e2e                                     |
| Session fixation          | Authenticated browser state; force a known identifier      | New cryptographic session and CSRF values after successful authentication                 | Compromised endpoint code can still misuse cookies                          | Randomness and rotation unit/e2e checks                |
| Session theft             | Opaque session; exfiltrate a browser cookie                | HttpOnly, host-only, SameSite, Secure in production, idle/absolute expiry, Redis hash     | Malware or TLS endpoint compromise remains out of scope                     | Cookie and session tests                               |
| CSRF                      | Authenticated mutation; cross-site request submission      | SameSite=Lax plus constant-time double-submit CSRF check                                  | Same-origin script compromise bypasses CSRF controls                        | Missing/invalid/valid CSRF e2e                         |
| Passkey replay            | Passkey login; reuse assertion or stale counter            | WebAuthn origin/RP verification, user verification, challenge consumption, counter checks | Authenticators with zero counters offer less clone detection                | Passkey replay/counter unit tests                      |
| Challenge replay          | OTP/passkey enrollment; reuse challenge state              | Redis `GETDEL`, short TTL, purpose and session/context binding                            | Redis failure can make ceremonies unavailable                               | Registration/authentication replay tests               |
| Malicious internal caller | Identity API; bypass public Gateway controls               | Loopback binding, no CORS, explicit internal token guard, endpoint allowlist              | Shared token theft until workload identity is introduced                    | Missing/malformed/incorrect token tests                |
| Sensitive log leakage     | PIN, OTP, phone, session, CSRF; accidental logging         | Metadata-only request logs, masked phone, hashed user agent/IP, classified errors         | Future logs require the same review discipline                              | Security masking tests and secret scan                 |
| Redis compromise          | OTP/session state; read or delete keys                     | Hashed OTP and session identifiers, bounded TTLs, authenticated Redis                     | An attacker can revoke sessions or attempt offline CSRF/session correlation | Redis TTL and no-plaintext tests                       |
| Database compromise       | Identity records; steal hashes/public keys and metadata    | Service-owned role/schema, Argon2id hashes, public-only passkey material, masked events   | Offline PIN guessing and metadata exposure remain possible                  | Migration ownership checks and schema review           |
| Identity unavailable      | Authentication availability; dependency outage             | Gateway short timeout, no mutation retries, readiness checks, normalized 503              | New login and session refresh are unavailable during outage                 | Gateway dependency-failure e2e                         |
| Browser storage leakage   | PIN, OTP, enrollment token, or session exposed to scripts  | Sensitive flow state remains in React memory; session is HttpOnly; only language persists | Same-origin script compromise can read active in-memory values              | Component storage assertions and secret scan           |
| URL/history leakage       | Authentication data copied into history, logs, or referrer | Fixed routes contain no phone, OTP, PIN, challenge, or token query values                 | Browser extensions may observe form interaction                             | Browser route review and security scan                 |
| Stale protected page      | Back/forward cache shows a revoked authenticated view      | Protected server checks plus reload on persisted `pageshow`; logout replaces history      | A compromised browser can still capture rendered safe user data             | Logout, restoration, and protected-route browser tests |
| WebAuthn phishing         | Credential used at an attacker-controlled origin           | Browser-enforced RP ID/origin plus server verification and user verification              | Users may still disclose fallback factors to a convincing phishing site     | Real virtual-authenticator registration/sign-in flow   |
| Accessibility exclusion   | Customer cannot complete secure authentication             | Keyboard operation, labels, focus movement, error summaries, translations, reduced motion | Device-specific assistive technology differences require broader testing    | Testing Library and axe browser coverage               |
